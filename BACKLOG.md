### §VM-01 — The Quest VM → *No Word for Wait* (NEW 2026-07-16)

> **Diagnostic (parent) lab report:** `lab-reports/lab-report-javascript-mud.md` — a structural read of the entire `<script>` block (five layers, four execution traces: program/UI/movement/quest-acceptance), plus the follow-up verification recorded below. **Not** a quest-by-quest audit. **Inc A child lab report LOCKED 2026-07-21:** `lab-reports/lab-report-vm01a-execbits-coroutine.md` (design-review-before-implementation; locks the `execBits`→generator transformation, the `ask` envelope, the driver, the five call-site wraps, the three design calls, and the test plan — see §RESUME NEWEST banner above). Policy: **Host/Script Separation Policy** in [CONTRIBUTING.md](CONTRIBUTING.md).
>
> **The unifying theme (matched to `story.md`): the engine tells, and cannot ask.** `story.md` is about a man who saw the Void and never managed to *ask anyone for help* — Froberger fixed it alone and it destroyed him. The quest engine commits the same act on the player: **you are told (`📋 <title>`), never asked.** Arrival + gate = `'active'`, announced in a `·`-joined message strip. There is no accept button — and the reason is not that nobody added one. **There is no state in which the VM is waiting for an answer.** (§PLAY-01 found the engine *knows what it won't transmit*; §VM-01 finds it **cannot receive**. Same sin, opposite direction.)
>
> **The architecture is already right — this track finishes §ARCH-01, it does not redesign it.** The file runs a proper embedded-scripting split twice over: three pure, world-injected, parity-fenced kernels (`MOVER`/`ROOMS`/`DUEL`, byte-identical to `js/*.js` with CI assertions), and a 258-line `QuestRuntime` executing 11,106 lines of `QUEST_DB` through the `BIT_CONTRACTS` opcode table. That 43:1 ratio is the achievement. **The defect is one small thing on top of it.**
>
> **Root cause — the VM has twelve opcodes and no jump instruction.** `execBits` (`21722`) in full: a `for` loop that looks up `HANDLERS[bit.kind]`, calls `h(bit, ctx)`, and ignores the return. No branch. No suspend. Three verified proofs, all grepped this session, none recalled:
>
> 1. **`choice` has a complete contract and an empty handler.** The contract (`21577`) is rigorous — requires `prompt` + `options`, validates ≥2 options each carrying a `label` and a `bits` array. The implementation (`21779`) is, in full: `choice(bit, ctx) { /* Phase 2: renderChoiceBlock(bit.prompt, bit.options, ctx) */ }`. **Zero quests use it** (`grep -c "kind:'choice'"` → 0). It was never written because **a synchronous `for` loop cannot wait for a human being.**
> 2. **`item_check` writes a predicate nobody reads.** `21777` sets `ctx._itemCheck = …`; a full-file grep returns that line and nothing else. It is a conditional in a language with no `if` — it evaluates and evaporates.
> 3. **`skill_check` works only by smuggling.** It is the one bit that branches, and it does so by hardcoding the branch *inside the leaf*: `resolveSkillCheck` → `execBits(pass ? bit.onPass : bit.onFail)` (`21750`). The sole conditional in the whole language is baked into one instruction rather than available to it.
>
> **Two missing words, and everything follows.** `wait` (no `yield` → no consent, no `choice`, no dialogue tree, no multi-step interaction, no `'abandoned'` status, no transactional bit chain — a throw mid-chain leaves half the effects applied with no rollback). `or` (no boolean nesting → each new OR shape has historically meant a new *term*; `itemsMinAny` was added for exactly one quest, `quest_wm_01`). **Prior art worth reading before Inc A:** Ink (Inkle) compiles narrative to JSON bytecode on a small VM and suspends at a `ChoicePoint` — structurally what this is; Yarn Spinner for dialogue; CEL / JSONLogic for Inc F (expression-AST-as-data, no parser needed).
