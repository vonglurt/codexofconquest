# r2h mesh bootstrap — static peer list (§MESH-01 b/c)
# One entry per line. Lines starting with # are ignored.
#
#   <host:port> [engineVer] [worldHash]     — a game server to gossip with
#   tracker <url>                           — a tracker to announce to (§MESH-01d);
#                                             in --tracker-mode this line instead names a
#                                             FEDERATION peer to sync tables with (§MESH-01-FU 12)
#
# The full bootstrap ladder, in order:
#   1. --peer host:port CLI flags
#   2. MESH_PEERS env (comma-separated)
#   3. peers-cache.json   (last-known live peers, written automatically)
#   4. this file
#   5. tracker / BOOTSTRAP_URLS (§MESH-01d)
#
# Only servers with an IDENTICAL (proto, engineVer, worldHash) will ever sync —
# see GET /api/manifest for yours. Publish your own list with:
#   curl localhost:1367/api/manifest
#
# Cross-machine reachability (§MESH-01-FU 1): the server binds 127.0.0.1 by
# default, so a real LAN/WAN mesh needs BOTH of:
#   --bind 0.0.0.0             (or BIND_ADDR=0.0.0.0)     — accept remote dials
#   --advertise <lan-ip>:1367  (or ADVERTISE_ADDR=…)      — what peers/trackers dial back
# With peers configured but a loopback bind (or localhost advertise) the server
# prints a ⚠ MESH REACHABILITY warning at startup and surfaces it on the
# worldbuilder Mesh tab (GET /api/mesh/status → reachability.warnings).
#
# Examples (commented out):
# 192.168.1.20:1367
# tracker http://tracker.example.org:1368
